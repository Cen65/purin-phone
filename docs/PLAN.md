# Purin · 发展计划

> 配套项目：`purin/`（本项目底座，原名 my-phone，2026-11 更名）。本计划从底座完成时点开始，向后分阶段推进（P0–P5 主体已交付，P6 为个性化打磨阶段）。
> 每个阶段都有明确验收标准，完成即可交付一个"可用的版本"，不追求一步到位。

## P0 · 底座（已完成 ✅）

浏览器里的"手机"：桌面 + App 注册表 + 聊天/联系人/便签/设置四个内置 App + OpenAI 兼容流式对话 + 主题 + 持久化。

- 手机壳（PhoneShell）：状态栏、桌面网格、Dock、底部导航、通知 Toast、应用错误边界
- App 系统：`registerApp` 注册表，App 之间通过事件总线与路由参数解耦
- AI 层：Provider 抽象 + openai-compatible 实现（SSE 流式、整段 JSON 兼容、模型列表、连接测试）
- 状态层：zustand + persist（localStorage），存储适配器可替换
- 测试：注册表 / SSE 解析 / 提示词组装 / 聊天流式生命周期，共 17 例

**验收**：`pnpm install --ignore-workspace && pnpm dev` 后可配置任意 OpenAI 兼容 API 并与角色流式聊天；`pnpm build && pnpm test` 全绿。

按价值密度排序（⭐ = 建议优先级；阶段列 = 建议归入）：

### A · 角色鲜活度（最核心的差距）
- ⭐⭐⭐ **主动消息** → ✅ **基础版已落地**：角色按「间隔+抖动」的节奏自己找话题发消息（未主动发过的角色启用后 3~10 分钟来第一条），写入会话 + 通知中心 + 聊天角标。角色级开关与作息（睡眠时段不打扰）在联系人编辑页；全局开关与最小间隔在设置页。应用打开期间运行（后台标签页切回时补一轮）；关站推送（Web Push/服务器侧 AMSG 式）留待。AI 自动发朋友圈已并入同一引擎（runMomentRound）。
- ⭐⭐⭐ **世界书 / 设定集**：词条支持 常驻/关键词/正则 触发、插入深度、优先级、生效场景；群聊可挂独立世界书 → P3 ✅ 已落地（正则+关键词+常驻+优先级+双插入位；插入深度按条数细分留待）
- ⭐⭐⭐ **记忆自动化**：定期把聊天记录巩固成记忆摘要、角色对用户的"印象档案" → ✅ 基础版落地（🧠 手动总结 + 阈值触发的自动巩固并写回 memory；**印象档案已落地**：聊天页 👁 手动生成 + **自动巩固**（攒够约 24 条自动刷新，游标/冷却防重，设置可关）；**情感模型已落地**：关键词好感度 ±（0~100 五档关系阶段）+ 心情推导，注入提示词影响语气冷热，聊天中随话自动涨落、编辑器可手调；**LLM 打分版可选**（设置开启，模型理解讽刺反话，每轮多一次小请求，与关键词法互斥））
- ⭐⭐ **情绪与亲密度**：好感度/亲密度等级随互动变化；角色"吃醋/黏人/主动"程度参数化 → P4
- ⭐⭐ **角色自主活动**：挂机时角色自己"过日子"（生成日常动态、日记）→ P4

### B · 聊天表达力
- ⭐⭐⭐ **生图**：让 TA"拍一张"（聊天生图）、朋友圈配图、头像生成；进阶"参考图锁脸"保持人物一致性 → P4 ✅ 基础版落地（/画 指令 + 设置生图模型 + IndexedDB 图片仓；朋友圈配图已落地：自动配图+本地选图，失败降级纯文字；**锁脸已落地**：角色编辑器挂最多 3 张参考图（IndexedDB），/画 与朋友圈配图自动走 /images/edits 图生图，服务商不支持时降级普通生图）

## 原则（所有阶段通用）

1. **底座稳定**：`src/core` `src/phone` `src/state` 的公共 API 只加不改（破坏性变更必须有迁移说明）。
2. **App 自治**：一个 App 的崩溃/报错不拖垮系统（已有 ErrorBoundary，保持）。
3. **先纵后横**：每个功能先在内置 App 打磨完整，再考虑抽象成 SDK。
4. **测试跟随**：核心逻辑（解析、状态、注册表）必须有单测；UI 以手工验收为主。
5. **授权干净**：不引入与项目授权冲突的代码；参考别人项目时只看"做什么"，不看"怎么写"。
