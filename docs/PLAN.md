# 布丁机 Purin · 发展计划

> 配套项目：`purin/`（本项目底座，原名 my-phone，2026-11 更名）。本计划从底座完成时点开始，向后分五个阶段。
> 每个阶段都有明确验收标准，完成即可交付一个"可用的版本"，不追求一步到位。

## P0 · 底座（已完成 ✅）

浏览器里的"手机"：桌面 + App 注册表 + 聊天/联系人/便签/设置四个内置 App + OpenAI 兼容流式对话 + 主题 + 持久化。

- 手机壳（PhoneShell）：状态栏、桌面网格、Dock、底部导航、通知 Toast、应用错误边界
- App 系统：`registerApp` 注册表，App 之间通过事件总线与路由参数解耦
- AI 层：Provider 抽象 + openai-compatible 实现（SSE 流式、整段 JSON 兼容、模型列表、连接测试）
- 状态层：zustand + persist（localStorage），存储适配器可替换
- 测试：注册表 / SSE 解析 / 提示词组装 / 聊天流式生命周期，共 17 例

**验收**：`pnpm install --ignore-workspace && pnpm dev` 后可配置任意 OpenAI 兼容 API 并与角色流式聊天；`pnpm build && pnpm test` 全绿。

## P1 · 聊天核心深化（已完成 ✅）

目标：把"能聊"变成"聊得舒服、聊得久"。

- [x] 停止生成（AbortController 贯穿 chatRunner → provider，单聊保留半截、群聊轮次中断）✅
- [x] 会话管理：清空会话、导出聊天记录 txt；群聊会话（新建/成员选择）✅（重命名、置顶留待 P3）
- [x] 消息操作：重新生成（单聊）、错误消息就地重试 ✅（编辑/删除单条留待）
- [x] Markdown 渲染：`src/core/md.ts` 零依赖实现（转义优先防注入；粗斜体/行内码/围栏码块/链接/引用）✅（未引入 marked/shiki，够用且无依赖）
- [x] 常用服务商预设：DeepSeek / OpenAI / Kimi / 硅基流动 / OpenRouter / Ollama 一键填 BaseURL ✅
- [x] 角色卡导入导出：`{type:"purin.character", version:1}` JSON（导入兼容旧 `my-phone.character`），通讯录导入/导出按钮 ✅
- [x] 上下文策略可调：窗口条数设置（10/20/40/80），空消息过滤 ✅（system 模板化留待）
- [x] 长回复渲染优化：分页渲染（默认渲染最近 60 条 +「加载更早」）✅（真虚拟滚动留待 P4，先够用）
- [x] 群聊（提前完成）：成员按序依次回复、单个失败不打断（fail-soft）、气泡带发言人 ✅
- [x] 角色长期记忆字段：memory 手动维护，注入 system 提示词 ✅（自动提取属 P2 记忆卡）

**验收**：与一个角色连续对话 100+ 条无性能劣化（分页渲染保证）；中断/断网/超时均有明确反馈与恢复路径；角色卡可在两台设备间迁移。

- [x] 通知中心：状态栏 🔔 下拉收件箱（最近 20 条）、未读角标、点击跳转 ✅
- [x] 锁屏：大时钟 + 最近未读 + 点击解锁（状态栏 🔒）✅
- [x] 群聊：多角色会话（P1 提前完成）✅（抢答/指定发言策略留待）
- [x] 朋友圈 / 动态：手动发帖 + ✨ 随机角色 AI 生成动态，点赞/评论/话题标签 ✅（定时自动发帖留待）
- [x] 来电：联系人页拨号 → 全屏通话界面（接听/拒接/快捷语/计时），挂断自动转写进普通聊天 ✅
- [x] 角色记忆：每角色 memory 字段注入提示词（P1 完成）✅（自动滚动压缩成记忆卡 **留待**）

**验收**：刷新/重启后一切状态还原（persist）；新增系统功能均为独立 App 或独立模块，未修改底座核心 API（只新增）。

## P3 · 扩展生态

目标：让别人（或未来的你）能不动核心地加东西。

- [ ] App SDK：`createApp()` 帮助函数 + 类型包，新 App 只需一个文件 + 一行注册
- [ ] 动态 App：应用市场页面，App 以 ESM 动态 import 加载（本地目录清单起步）
- [ ] 主题包：主题 JSON 化（名称 + CSS 变量 + 壁纸），设置里一键切换/导入
- [ ] 角色卡生态：定一个公开的角色卡 JSON Schema（人设、开场白、示例对话、记忆种子）
- [ ] 脚本钩子：事件总线暴露给 App（`bus.on("chat:reply-finished")` 自动玩梗回复等）

**验收**：新增一个第三方 App / 主题 / 角色卡均不需要修改 `src/phone`、`src/state` 任何文件，只做"注册"动作。

## P4 · 增强能力

目标：多模态与多端。

- [ ] 生图：Provider 增加 `generateImage`，聊天中 `/画 xxx` 触发
- [ ] TTS / ASR：角色语音消息 + 语音输入（Web Speech API 起步，服务商 TTS 进阶）
- [ ] PWA：manifest + Service Worker，可安装到桌面/手机主屏，离线打开
- [ ] 云备份：导出/导入全量数据（JSON 文件起步，WebDAV/Gist 同步进阶）
- [ ] 多端适配：宽屏双侧栏布局（手机居中 + 侧边会话列表）

**验收**：手机安装到主屏后离线可打开查看历史；一条语音消息从录制到播放全流程可用。

## P5 · 商用化：账号 / 激活码 / 管理后台（可随时提前启动）

目标：售卖激活码，一码绑定一台设备，配套管理后台。详细设计见 `docs/COMMERCIAL-DESIGN.md`。

- [x] M1 授权接缝：`src/core/entitlement.ts`（Provider 注册表 + 设备指纹 + 开放模式默认值）+ 设置页授权状态展示 ✅
- [x] M2 License Server 最小版：`purin/license-server/`（Node 23 原生 TS 零运行时依赖 + SQLite + 管理后台 /admin + Docker/Caddy 一键部署）✅
- [x] M3 管理后台 MVP：批量生码导出、按码/备注/设备查询、解绑/封禁/恢复/延期、统计卡片 ✅（发卡 webhook 未做：按用户要求走线下收款，暂不需要）
- [x] M4 客户端闭环：ActivationGate 激活页 + commercial.json 开关（open=单机 / licensed=商用）✅（AI 网关 Provider 属 P4 服务端代理范畴，未做）
- [ ] M5 运营完善：到期续费提醒、简表盘导出（已有 stats 基础）

**关键决策**：纯前端授权墙防不住破解，商用约束力来自服务端价值（AI 代理/云功能）；
推荐"卖服务"模式（用户不接触 API Key）。**验收**：一枚码在第二台设备激活被拒绝，
解绑后可重新绑定；封禁的码心跳即失效；发卡平台支付成功自动标记售出。

### B · 聊天表达力
- ⭐⭐⭐ **生图**：让 TA"拍一张"（聊天生图）、朋友圈配图、头像生成；进阶"参考图锁脸"保持人物一致性 → P4
- ⭐⭐⭐ **TTS 语音**：语音消息 + 通话真出声（MiniMax/FishAudio/ElevenLabs 三选一起步）→ P4
- ⭐⭐ **表情包系统**：用户添加表情包链接并命名，角色按名字理解并用表情回复 → P4
- ⭐⭐ **消息互动玩法**：红包/转账/虚拟货币（存钱罐）、位置、相册 → P4
- ⭐ **气泡/背景美化**：iMessage 玻璃/经典气泡切换、按聊天自定义背景、每聊天独立备注与头像 → P3

### C · 生活陪伴场景（差异化 App 生态）

## 原则（所有阶段通用）

1. **底座稳定**：`src/core` `src/phone` `src/state` 的公共 API 只加不改（破坏性变更必须有迁移说明）。
2. **App 自治**：一个 App 的崩溃/报错不拖垮系统（已有 ErrorBoundary，保持）。
3. **先纵后横**：每个功能先在内置 App 打磨完整，再考虑抽象成 SDK。
4. **测试跟随**：核心逻辑（解析、状态、注册表）必须有单测；UI 以手工验收为主。
5. **授权干净**：不引入与项目授权冲突的代码；参考别人项目时只看"做什么"，不看"怎么写"。
